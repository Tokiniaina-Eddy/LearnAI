PETIT CAHIER DES CHARGES
Plateforme d'apprentissage personnalisée avec IA

Version : 1.0
Date : 15 août 2026

1. PRÉSENTATION DU PROJET

Nom provisoire : LearnAI

LearnAI est une plateforme web d'apprentissage personnalisé utilisant un LLM OpenAI pour construire, générer et adapter automatiquement le parcours d'apprentissage d'un utilisateur.

L'objectif est de proposer une expérience différente d'une plateforme de cours classique : le système tient compte du niveau, des objectifs, du temps disponible, des résultats aux quiz et exercices ainsi que des points faibles de l'apprenant afin d'adapter progressivement son parcours.

Exemple :
Un utilisateur souhaite apprendre FastAPI, indique son niveau débutant et dispose d'une heure par jour. La plateforme réalise une évaluation initiale, génère un parcours adapté, propose des cours et exercices, puis analyse les résultats pour ajuster le parcours.

2. OBJECTIFS

Objectif principal :
Créer une plateforme capable de personnaliser automatiquement l'apprentissage grâce à l'IA.

Objectifs secondaires :
- Évaluer le niveau initial de l'utilisateur.
- Générer un parcours pédagogique personnalisé.
- Générer des cours, exemples, quiz et exercices.
- Suivre la progression de l'apprenant.
- Identifier ses points forts et ses lacunes.
- Adapter le parcours en fonction des résultats.
- Fournir un tuteur IA capable d'expliquer les notions.
- Donner des statistiques et une vision claire de la progression.
- Préparer une architecture pouvant évoluer vers un véritable produit SaaS.

3. UTILISATEURS

3.1 Apprenant
L'apprenant peut :
- créer un compte ;
- définir son objectif d'apprentissage ;
- indiquer son niveau ;
- indiquer son temps disponible ;
- passer une évaluation initiale ;
- suivre son parcours ;
- consulter les cours ;
- répondre aux quiz ;
- réaliser des exercices ;
- demander de l'aide au tuteur IA ;
- consulter sa progression ;
- consulter sa carte de compétences.

3.2 Administrateur
L'administrateur peut :
- gérer les utilisateurs ;
- consulter les parcours générés ;
- gérer les contenus ;
- consulter les statistiques globales ;
- surveiller l'utilisation de l'IA ;
- gérer les paramètres de la plateforme.

4. FONCTIONNALITÉS PRINCIPALES

4.1 Authentification
- Inscription
- Connexion
- Déconnexion
- Gestion du profil
- Réinitialisation du mot de passe

4.2 Profil d'apprentissage
L'utilisateur renseigne :
- objectif ;
- domaine ou technologie à apprendre ;
- niveau estimé ;
- temps disponible par jour/semaine ;
- durée souhaitée ;
- préférences d'apprentissage.

Le système conserve également :
- compétences maîtrisées ;
- compétences faibles ;
- progression ;
- résultats ;
- historique d'apprentissage.

4.3 Évaluation initiale
La plateforme génère une évaluation adaptée à l'objectif.

L'évaluation peut contenir :
- questions théoriques ;
- questions à choix multiples ;
- petits exercices ;
- exercices pratiques selon le domaine.

À la fin, le système calcule une estimation du niveau et une première carte de compétences.

4.4 Génération du parcours
OpenAI génère un parcours structuré comprenant :
- modules ;
- objectifs de chaque module ;
- leçons ;
- quiz ;
- exercices ;
- projet(s) pratique(s) ;
- ordre recommandé ;
- niveau de difficulté.

Le parcours doit être retourné dans un format structuré (JSON) afin d'être enregistré dans la base de données.

4.5 Cours personnalisés
Chaque leçon peut contenir :
- explication ;
- exemples ;
- conseils ;
- points importants ;
- exercices ;
- mini-quiz.

Le contenu doit être adapté au niveau de l'utilisateur.

4.6 Quiz
Le système permet :
- génération automatique de questions ;
- réponses à choix multiples ;
- correction automatique ;
- calcul du score ;
- explication des erreurs ;
- enregistrement des tentatives.

4.7 Exercices pratiques
L'utilisateur peut réaliser des exercices adaptés à son niveau.

Pour les exercices de programmation :
- éditeur de code ;
- soumission du code ;
- tests automatiques lorsque possible ;
- analyse complémentaire par OpenAI ;
- feedback pédagogique.

4.8 Tuteur IA
Un assistant IA est disponible pendant l'apprentissage.

Il doit pouvoir :
- expliquer une notion ;
- reformuler un cours ;
- donner des exemples ;
- aider à comprendre une erreur ;
- proposer des pistes sans donner systématiquement directement la solution ;
- adapter ses explications au niveau de l'apprenant.

Le tuteur doit disposer du contexte du cours et, lorsque nécessaire, des données de progression de l'utilisateur.

4.9 Adaptation automatique du parcours
Après les quiz et exercices, le système analyse les résultats.

Exemple :
Si l'utilisateur maîtrise HTTP mais rencontre des difficultés avec REST, la plateforme peut :
- ajouter une révision ;
- générer des exercices supplémentaires ;
- ralentir la progression ;
- recommander une leçon ;
- modifier l'ordre de certaines activités.

Le parcours devient donc dynamique.

4.10 Carte de compétences (Skill Map)
Pour chaque objectif, le système suit différentes compétences.

Exemple :
HTTP : 85 %
REST : 60 %
Routing : 75 %
Database : 45 %
Authentication : 25 %

La carte permet d'identifier rapidement les points forts et les lacunes.

4.11 Tableau de bord
Le dashboard doit afficher :
- objectif actuel ;
- progression globale ;
- module actuel ;
- prochaine activité ;
- score moyen ;
- temps d'apprentissage ;
- compétences ;
- points faibles ;
- historique récent.

4.12 Gamification
Fonctionnalités prévues :
- XP ;
- niveaux ;
- badges ;
- séries de jours d'apprentissage (streak) ;
- objectifs quotidiens.

Cette partie pourra être développée après le MVP.

5. INTELLIGENCE ARTIFICIELLE

Le projet utilisera l'API OpenAI comme moteur LLM.

Principales utilisations :
- génération de parcours ;
- génération de cours ;
- génération de quiz ;
- génération d'exercices ;
- correction et feedback ;
- analyse des résultats ;
- adaptation du parcours ;
- tutorat conversationnel.

Les réponses destinées à être enregistrées dans la base doivent utiliser des sorties structurées lorsque cela est pertinent afin de limiter les erreurs de format.

Important :
Le LLM ne doit pas être la seule source de vérité pour les évaluations de code. Lorsque cela est possible, les exercices de programmation doivent être vérifiés par des tests automatisés, puis l'IA peut fournir une explication pédagogique.

8. FLUX PRINCIPAL

1. L'utilisateur crée son compte.
2. Il renseigne son objectif.
3. Il renseigne son niveau et son temps disponible.
4. La plateforme génère une évaluation.
5. L'utilisateur réalise l'évaluation.
6. Le système analyse les résultats.
7. OpenAI génère un parcours personnalisé.
8. Le parcours est enregistré dans la base.
9. L'utilisateur commence les cours.
10. Il réalise des quiz et exercices.
11. Les résultats sont enregistrés.
12. Le système met à jour les compétences.
13. L'IA analyse les lacunes.
14. Le parcours est adapté si nécessaire.
15. L'utilisateur continue jusqu'au projet final.

9. MVP

La première version doit contenir uniquement les fonctionnalités essentielles :

- Authentification
- Profil d'apprentissage
- Création d'un objectif
- Évaluation initiale
- Génération du parcours par OpenAI
- Affichage des modules et leçons
- Génération/présentation des quiz
- Correction et score
- Suivi de progression
- Première version du Skill Map
- Tuteur IA basique
- Adaptation simple du parcours

Les fonctionnalités suivantes seront développées après le MVP :
- éditeur de code ;
- exécution sécurisée du code ;
- tests automatisés ;
- gamification avancée ;
- badges ;
- statistiques avancées ;
- administration complète ;
- abonnement SaaS.

10. SÉCURITÉ

Le système devra prévoir :
- authentification sécurisée ;
- mots de passe hashés ;
- contrôle d'accès ;
- validation des données ;
- protection des API ;
- limitation des requêtes vers OpenAI ;
- protection des clés API ;
- journalisation des erreurs.

Pour l'exécution de code utilisateur, un environnement isolé devra être utilisé. Le code ne doit jamais être exécuté directement sur le serveur principal.

11. QUALITÉ ET PERFORMANCE

Le système doit :
- être responsive ;
- avoir une interface claire ;
- gérer les erreurs de l'API OpenAI ;
- éviter les appels IA inutiles ;
- enregistrer les réponses importantes ;
- utiliser des réponses structurées lorsque nécessaire ;
- prévoir une stratégie de limitation des coûts ;
- permettre l'évolution vers plusieurs domaines d'apprentissage.

12. ÉVOLUTION FUTURE

Évolutions possibles :

13. RÉSULTAT ATTENDU

À la fin du projet, l'utilisateur doit pouvoir arriver avec un objectif d'apprentissage, recevoir automatiquement un parcours adapté à son niveau, apprendre à travers des contenus générés et structurés, être évalué, recevoir un feedback personnalisé et voir son parcours évoluer en fonction de ses résultats.

Le projet doit démontrer la maîtrise de :
- développement frontend ;
- développement backend ;
- API REST ;
- base de données ;
- intégration d'un LLM ;
- prompting et sorties structurées ;
- logique d'adaptation ;
- automatisation ;
- sécurité ;
- architecture d'une application moderne.
